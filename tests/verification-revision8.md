## Faults that changed the implementation

An out-of-order file read left two import confirmations on screen even though the file picker named only the second file. Reversing the read completions in a browser produced two buttons. Selection invalidation fixed it, and the same check now requires exactly one. Deleting an observation destroyed its dialog opener and lost keyboard focus. A failing focus check led to a stable return target. An imported 240-character skill title overflowed a 320 px viewport until the ledger heading could wrap. The browser suite reproduces these cases directly.

A review of previously passing tests also found an erroneous expectation about deleting older exposures. A familiar retry should keep its prior-exposure context after deletion, correction or projection to another file. The regression suite checks the claimed capabilities after those operations. Keeping a minimal familiarity marker permits erasing the earlier record without keeping its private text.

Review did not establish cross-browser assistive-technology usability, learner retention, or a reliable completion time for the original questions. The next study should collect an actual unassisted solution and a later unfamiliar transfer item under the agreed conditions.
